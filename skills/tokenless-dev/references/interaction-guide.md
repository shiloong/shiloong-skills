# 交互规范（tokenless-dev 通用）

适用于 tokenless-dev 所有子命令在运行期与用户发生的**决策型交互**（RPM 仓库路径确认、版本号选择、超时等待、校验不一致、构建断言缺项、CHANGELOG 审核等）。

## 核心原则

**「先正文呈现背景 → 再用极简 AskUserQuestion 提问」**

- 所有上下文信息（版本号、tag、文件大小、SHA256、直链、受影响范围、命令示例等）**一律在对话正文**以 Markdown 表格 / 代码块 / 列表呈现
- AskUserQuestion 的 `question` 字段**仅保留动作性问句**，例如 `请选择下载方式：` / `是否继续等待？` / `SHA256 不一致，是否继续？` / `请确认 RPM 仓库路径：`
- 选项 `label` ≤ 12 字（如 `A. 自动下载（推荐）`），`description` 1 句说明差异或后果
- 推荐选项放首位，必要时在 label 末尾加 `（推荐）`

## 典型场景模板

| 场景 | 正文需呈现 | question 示例 | 选项（示例） |
|------|-----------|---------------|------------|
| RPM 仓库路径确认 | 推断路径 / 检测到的 `.git`/`package-tokenless.sh` / 当前 spec 版本 | `请确认 RPM 仓库路径：` | 使用推断路径 / 手动指定 / 取消 |
| 下载方式选择 | tag / asset / size / sha256 / 直链 / 手动命令 / 影响说明 | `请选择下载方式：` | 自动下载(推荐) / 我已手动下载 / 取消 |
| 自动下载/构建超时 | 已等时长 / 累计上限 / 临时文件当前大小 | `是否继续等待？` | 再等 5 分钟 / 重试 / 切手动 / 取消 |
| SHA256 不一致 | 期望值 / 实际值 / 文件路径 | `校验未通过，如何处理？` | 重新下载 / 切手动下载 / 取消 |
| 构建断言缺项 | 失败断言列表 / 最后 40 行日志路径 | `构建校验失败，是否继续？` | 查看日志 / 重试构建 / 中止 |
| CHANGELOG 草稿审核 | Markdown 渲染的 CHANGELOG 草稿（按分类列出） | `请审核 CHANGELOG：` | 确认写入 / 修改 / 取消 |
| 版本号建议 | 当前 Cargo.toml 版本 / 最新 tag 版本 / commits 分析 / 建议值 | `请确认目标版本号：` | 采用建议 / 自定义 / 取消 |

## 反例（禁止）

- ❌ 把大段 tag / size / sha256 / URL / 手动命令全部塞进 `question` 字段 → UI 换行拥挤，信息不可读
- ❌ 用多句复合问句（`A 和 B 请选一个，如果都不想也可以 C...`）→ 问意不清
- ❌ 选项 label 过长或带完整 URL → 按钮溢出
- ❌ 正文与选项内容重复冗余 → 提高认知成本

## 与 SKILL.md 全局约定的关系

本规范细化 [SKILL.md](../SKILL.md) 中"关键节点需用户确认"的执行方式，所有子流程（fix / release / distribute / review）在发起用户确认时均应遵循。
